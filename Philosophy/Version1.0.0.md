# 1.0.0

I've been watching a lot of talks on YouTube recently about how to design languages, so you'll find me writing things that aren't really relevant to me now.

What does it mean to be 1.0? You need to know what kind of language: functional or imperative. You can't change this.

The next releases are filling in the gaps that you didn't have enough time to do initially before the release.

In a language you can add but you can't remove. If you take something away from the language it breaks people code.

You need justification of what you add because one new feature is more complexity and learning curve.

You have to be ruthless when adding a new feature. You need to do a cost benefit analyzes not onl compilers but software in general. Should we do X and how much is it going to cost us? You should think of every new feature as -500 points but you have to gain all of them back.
